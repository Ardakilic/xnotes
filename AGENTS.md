# AGENTS.md — instructions for LLM agents working in this repo

## The one rule: Docker-only toolchain

The host has **no Node.js and no npm — and must never need them**. Every workflow runs through Makefile targets, each of which is a `docker run` of the pinned image `node:22-bookworm-slim`:

```sh
make setup        # npm ci (or npm install if no lockfile)
make typecheck    # tsc --noEmit
make lint         # eslint + prettier --check
make test         # vitest unit tests
make integration  # docker compose: real dufs + adobe/s3mock + test container
make build        # wxt build (chrome) + wxt build -b firefox
make zip          # store zips (firefox zip auto-includes sources zip)
make dev          # wxt dev (chromium); make dev-firefox for firefox
```

- **Always verify your changes with `make typecheck`, `make lint`, `make test`** (plus `make integration` if you touched `src/sync/`, `tests/integration/`, or the compose file). All must be green before you call work done.
- To run arbitrary npm binaries: `docker run --rm -v xnotes-npm-cache:/root/.npm -v "$PWD":/app -w /app node:22-bookworm-slim npx <tool>`.
- Never `npm install` on the host. Never add scripts that assume host Node.
- `node_modules/` contains **Linux** binaries (created in containers) — that is correct; the host never executes them.

## Project

xNotes — a cross-browser MV3 extension (WXT + strict TypeScript, vanilla DOM) that stores private notes for X/Twitter profiles locally, with optional E2E-encrypted sync to user-owned WebDAV/S3 storage. The normative spec for the current change lives in `openspec/changes/add-xnotes-extension/` (proposal, design, delta specs, tasks). When implementation and spec disagree, investigate which is right; if reality wins (it has before — see Gotchas), update the spec artifacts in the same change.

## Architecture invariants (do not break)

- **Single write path:** only `src/core/storage.ts` touches `browser.storage.local`. All other modules go through its functions.
- **Validate-by-construction:** parsers rebuild valid objects from `unknown` (`toNoteRecord`, `toStoreV2`). **Zero `as` assertions** anywhere in `src/` and `entrypoints/` — also enforced socially; find a way to type it instead.
- **No `chrome.*`:** only `browser` from `wxt/browser`. ESLint enforces this.
- **Deletes write tombstones** (`StoreV2.tombstones`), never physical-only removal — sync correctness depends on it. Tombstones GC after 90 days (`merge.ts`).
- **Merge is sacred:** `merge(local, remote)` must stay pure, commutative, idempotent, lossless. Tie-breaks must stay position-independent (tombstone beats note at equal ts; note-vs-note by canonical serialization). Randomized commutativity tests guard this.
- **Local-only keys never sync:** `xnotes:sync-state`, `xnotes:settings`, `xnotes:view` stay local. The uploaded blob is exactly the `StoreV2` (optionally wrapped in the crypto envelope).
- **Passphrase never persists:** memory-only in the background; any change that writes it anywhere is a spec violation.
- **Background is service-worker-strict:** state in storage, listeners registered synchronously at top level, `browser.alarms` for scheduled work (the one documented exception is the 10 s debounce `setTimeout` in `scheduler.ts` — see its `ponytail:` comment for why and what backstops it).
- **Encryption envelope** is `{v:1, cipher:"aes-256-gcm", kdf:"pbkdf2-sha256", iter≥600000, salt, iv, data}`; decrypt must reject `iter` below the minimum.

## Conventions

- TypeScript strict set is in `tsconfig.json` (extends `.wxt/tsconfig.json`, generated by `wxt prepare` during `make setup`). Notable: `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `verbatimModuleSyntax` (use `import type`).
- Prettier: single quotes, printWidth 100. Run formatting via `docker run ... npm run format` if `make lint` complains.
- **No comments** except `ponytail:` markers documenting a deliberate simplification and its ceiling/upgrade path.
- Tests are colocated (`foo.test.ts` next to `foo.ts`); DOM tests start with `// @vitest-environment happy-dom` (happy-dom is installed). Integration tests live in `tests/integration/` and only run via `make integration`.
- Keep diffs minimal; delete over adding; reuse existing helpers before writing new ones.

## Gotchas (learned the hard way — don't rediscover)

- **dufs ignores `If-Match` on PUT** (verified v0.46.0; returns 201 for stale etags) and its **PUT responses carry no ETag**. `WebdavAdapter` therefore HEAD-compares before conditional PUTs and fetches the ETag via HEAD after PUT. `If-None-Match` on GET *does* work (304).
- **adobe/s3mock also ignores `If-Match` on PUT** (same class as Backblaze B2) — integration tests exercise the HEAD-compare fallback against it; the 412 mapping is unit-tested with mocks.
- **S3 conditional headers need quoted entity-tags** — the adapter strips quotes on read and re-quotes on write (`quoteEtag`).
- **macOS port 5000 is AirPlay Receiver** — probing dufs on `localhost:5000` from the host hits Apple's server (403 + `Server: AirTunes`). Probe via the Docker network instead.
- **macOS ships GNU Make 3.81** — Makefile targets cannot contain `:` (hence `dev-firefox`, not `dev:firefox`).
- **dufs docker image is scratch-based** — no shell; mount a tmpfs at `/data` instead of `mkdir`. Auth rules need the `user:pass@/:rw` scoped form.
- **fake-browser quirks** (`@webext-core/fake-browser`): `permissions.request` is overloaded (promise|callback) so `vi.spyOn(...).mockResolvedValue` fails typecheck — use `mockImplementation(() => Promise.resolve(true))`; `runtime.onMessage` listeners must use `sendResponse` + `return true` (promise returns don't work); unmocked APIs throw `MockNotImplementedError`.
- **`crypto.subtle` settles on the event loop**, not in the microtask flush — with `vi.useFakeTimers()`, assertions after a fake-timer-advanced async chain may need `vi.useRealTimers()` + `vi.waitFor(...)` (see the debounce tests in `src/sync/scheduler.test.ts`).
- The integration compose file sets `name: xnotes-integration` — keep it; the default project name collides with other compose stacks on dev machines.

## OpenSpec workflow

Planning artifacts live in `openspec/`. Validate the active change after touching specs/tasks:

```sh
openspec validate "add-xnotes-extension"
```

Task checkboxes in `openspec/changes/add-xnotes-extension/tasks.md` are marked `[x]` only when actually done and verified.

## Manual verification

Anything requiring a real browser/backend is tracked in `MANUAL_TESTING.md` — add entries there when you implement something not unit-testable, rather than claiming it verified.
